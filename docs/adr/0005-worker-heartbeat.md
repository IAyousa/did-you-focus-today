# 计时心跳置于 Web Worker，规避后台标签页节流

番茄钟的到点提醒（响铃、桌面通知、标题闪烁）全部由计时心跳触发，而浏览器为省电对后台标签页实施阶梯式节流：轻度限频 1 次/秒 → 隐藏超 5 分钟后重度限至约 1 次/分钟 → 更久近乎冻结。线上实测（2026-09-11）：切去其他标签页学习约 10 分钟后，主线程 `setInterval` 心跳停摆，到点既不响铃也不发通知，切回页面才补触发。提醒是本工具的存在理由（"提醒保节奏"），且 ADR-0003 已禁止暂停——用户切走学习是常态而非异常，后台失铃不可接受。

决定：权威心跳移入 Web Worker（Worker 内定时器不受页面可见性节流约束，其 postMessage 可唤醒被节流的主线程），驱动倒计时刷新与 `toAlert` 触发；主线程自身的 interval 仅保留为 Worker 创建失败时的降级兜底。计时本体本就基于墙钟差值（`endsAt - now`），节流只影响提醒的及时性、不影响时长精度——此修复补的正是及时性。

## Considered Options

- Web Worker 心跳（选定）：后台准时响铃，代价是多一个 worker 文件与一条降级路径
- 维持 setInterval ＋ 在使用说明里写"切回页面才会响"：被否决——把核心功能失守写成文案，等于承认提醒不成立

## Consequences

- 桌面通知依赖心跳及时性，修复后"后台收到通知"才真正成立；Android Chrome 页面上下文不支持 Notification 构造器，属环境限制，在通知状态行如实标注，留待 PWA（service worker 通知）解决
